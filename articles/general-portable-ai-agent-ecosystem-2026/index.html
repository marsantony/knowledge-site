    可攜式 AI Agent 生態系：GitAgent、OpenClaw、NemoClaw 比較與實務路線

    重點¶

    • GitAgent 是開放規格標準（spec only），定義 agent 的三個核心檔案（agent.yaml + SOUL.md + SKILL.md），可匯出到 9+ runtime（Claude Code、OpenAI、CrewAI 等）
    • OpenClaw 是自主 AI Agent 框架（有 runtime），支援全通訊平台整合（WhatsApp、Telegram、Discord、LINE 等），所有狀態存為純文字檔，天生 Git 友善
    • NemoClaw 是 NVIDIA 的安全封裝層（2026-03-16 GTC 發表，alpha），在 OpenClaw 外包四層防禦沙箱（filesystem / network / process / inference）
    • 三者不互斥：GitAgent 定義「agent 長什麼樣」，OpenClaw 負責「agent 怎麼跑」，NemoClaw 處理「agent 怎麼安全地跑」
    • 已有成熟 Claude Code 設定的使用者，現有的 CLAUDE.md + skills + memory 本身就是一種可攜 agent 定義，不需要急著遷移

    背景¶

    2026 年初，「每個人身上都要帶著一組自己設計的 Agent」成為趨勢。核心概念是：agent 的人格（SOUL）、技能（SKILL）、記憶（Memory）不該綁定任何平台，而是用 Git repo 管理，隨時可遷移到不同的 runtime。

    三者架構比較¶

    GitAgent OpenClaw NemoClaw
    本質 開放規格標準 自主 AI Agent 框架 安全封裝層
    有 Runtime 無，靠 adapter 轉接 有，完整 agentic loop 在 OpenClaw 外包沙箱
    核心檔案 agent.yaml + SOUL.md + SKILL.md SOUL.md + AGENTS.md + SKILL.md + IDENTITY.md + USER.md 繼承 OpenClaw + policy YAML
    成熟度 極早期（v0.1.0，2026-02 建立） 活躍（319k+ stars） Alpha（2026-03-16 發表）

    GitAgent 技術細節¶

    三個核心檔案¶

    • agent.yaml：清單檔，定義模型偏好、技能列表、子 agent 組成、合規設定、A2A 協議
    • SOUL.md：人格定義（匯出時變成 system prompt），建議包含 Core Identity、Communication Style、Values、Domain Expertise
    • SKILL.md：技能模組，遵循 agentskills.io 開放標準（已被 30+ 工具採用，包括 Claude Code、Cursor、Codex）

    Adapter 系統¶

    一份定義匯出到多種格式：claude-code（CLAUDE.md）、openai（Python）、openclaw（JSON）、crewai（YAML）、system-prompt（Markdown）等。也支援從 CLAUDE.md、.cursorrules 反向匯入。

    Git-Native 工作流¶

    • branch promotion（dev → staging → main）做 agent 版本管理
    • PR review 做 human-in-the-loop
    • gitagent validate --compliance 做 CI/CD 驗證

    風險¶

    主要作者來自 Lyzr AI（agent 平台公司），spec 還在 0.1.0，設計隨時可能大改。

    OpenClaw 技術細節¶

    架構¶

    Gateway（WebSocket 控制平面）管理所有通訊平台連線，Agent Runtime 處理 context 組裝 → 模型推理 → 工具執行 → 串流回覆 → 持久化。

    獨特功能：steering while streaming — 訊息可在 agent 執行中插入，中斷正在跑的流程。

    Context Bootstrap¶

    新 session 第一輪載入五個檔案：AGENTS.md（指令 + 記憶）、SOUL.md（人格）、TOOLS.md（工具慣例）、IDENTITY.md（身份標記）、USER.md（使用者資訊）。

    安全問題¶

    • 4.2 萬個未保護的 gateway 暴露在公網
    • 「ClawJacked」零點擊漏洞
    • 中國 CNCERT 發過正式安全警告
    • 維護者自己都說：「如果你不懂 command line，這個專案對你來說太危險了」

    NemoClaw / OpenShell 安全架構¶

    四層防禦（Defense in Depth）¶

    層 保護範圍 可否熱更新
    Filesystem 限制讀寫路徑 建立時鎖定
    Network 攔截所有對外連線 可熱更新
    Process 防止提權和危險 syscall 建立時鎖定
    Inference 攔截模型 API 呼叫，導向受控後端 可熱更新

    Privacy Router¶

    Agent 用雲端模型時，privacy router 負責剝除/注入 credentials，敏感 context 保留在本地。搭配 Nemotron 本地模型形成 hybrid local+cloud 架構。

    部署模式¶

    Blueprint 架構：Resolve → Verify（密碼學雜湊）→ Plan → Apply，每次部署可重現、可稽核。底層是 K3s Kubernetes cluster 跑在單一 Docker container 裡。

    支援的框架不只 OpenClaw，也包括 Claude Code、OpenCode、Codex。

    Claude Code 使用者的對應關係¶

    GitAgent / OpenClaw 概念 Claude Code 對應
    SOUL.md（人格） CLAUDE.md 中的規範和工作流
    SKILL.md（技能） .claude/skills/ 自訂 skill
    memory/（記憶） .claude/projects/.../memory/
    hooks/（生命週期） settings.json 中的 hooks
    config/（環境設定） settings.json / settings.local.json

    務實的遷移路線¶

    1. 現在：確保現有 agent 定義有完整 Git 備份，定期 review memory 避免記憶污染
    2. 觀望期：等 NemoClaw 到 beta（預估 1-2 個月），用 GitAgent CLI 試玩匯入/匯出評估轉換品質
    3. 評估 OpenClaw：如果有跨通訊平台需求，用 Docker 隔離試玩，只接測試帳號
    4. 正式採用：NemoClaw 穩定後，Docker 一鍵部署 + policy YAML 定義安全邊界

    記憶管理最佳實踐¶

    （來自社群經驗）

    • 定期備份 agent 的人格和記憶
    • 定期 review memory，檢查是否有意外寫入的指令（「記憶污染」）
    • LLM 是文字接龍，一旦記憶裡有奇怪的指令，它會忠實執行
    • 用 Git diff 審查記憶變更，比人工逐條看更可靠
    • 可以用特定 prompt 從既有 LLM 匯出記憶，但受 context summarization 限制，不可能完整倒出
