    MCP 已死？2026 年論戰始末、替代方案比較與決策框架

    重點¶

    • 「MCP 已死」論戰由 Eric Holmes 的文章（2/28）引爆，Perplexity CTO 和 YC CEO Garry Tan 在 Ask 2026（3/11）加碼，引發社群牆倒眾人推
    • MCP 最致命的問題是 Token 開銷：掛 3 個 MCP Server（GitHub + Slack + Sentry）的 40 個工具，吃掉 72% context window（143,000 / 200,000 tokens）
    • Scalekit 的 75 次對照實驗顯示：MCP 成本是 CLI 的 4~32 倍，可靠性只有 72%（vs CLI 100%），月費 $55.20 vs $3.20
    • 業界共識收斂為分層架構：CLI（本機）→ Skills（流程引導）→ API（遠端服務）→ MCP（僅限需要多租戶 OAuth / 跨平台發布 / Agent 對 Agent 通訊的場景）
    • MCP 沒有真正死亡（97M SDK 下載、Linux Foundation 背書），但不再是預設答案

    反對 MCP 的主要論點¶

    1. Token 浪費

    每個 MCP 工具消耗 550~1,400 tokens（名稱 + 描述 + JSON Schema + 欄位說明 + enum），全部預載到每次對話，不管有沒有用到。Cloudflare 的 2,500 個 API endpoints 如果都轉成 MCP 工具，需要 117 萬 tokens。他們改用 Code Mode（兩個 meta-tool + typed SDK），只需 ~1,000 tokens，減少 99.9%。

    2. 可靠性不足

    MCP 的失敗來源包括 TCP 連線逾時、Server 程序管理、初始化失敗。CLI 是單純的二進位檔，沒有背景程序。

    3. 除錯困難

    MCP 除錯要翻 JSON transport log；CLI 直接重跑指令就好。

    4. 安全風險

    Tool poisoning（36.5% 成功率）、Rug pull、Prompt injection、Cross-server 攻擊。2025 年 Supabase 的 Cursor Agent 被工單中的 SQL injection 攻破。

    支持 MCP 的論點¶

    1. 企業治理

    OAuth 2.1 集中管理、多租戶授權、稽核軌跡、SSO 整合。CLI 把 credential 存檔案，管理和安全性不如 OAuth 流程。

    2. 跨平台發布

    一個 MCP Server 同時支援 Cursor、Claude Desktop、ChatGPT、Windsurf。用 CLI 則每個平台各寫一套。

    3. 沒有 CLI 的雲服務

    Notion、Figma、Slack 只有 API 沒有 CLI，MCP Server 是目前最便利的標準化存取層。

    4. 動態工具發現

    MCP 支援 runtime 動態註冊/移除工具，靜態 CLI 無法做到。

    MCP vs Skills vs CLI vs API 比較¶

    面向 MCP Skills CLI Web API
    本質 連接層 知識層 執行層 服務層

    可靠性 一般 高 極高 取決於 API
    認證 OAuth 2.1 不涉及 用既有 CLI auth 用既有 API auth
    跨平台 強 限 Claude 生態 需各平台整合 通用

    Skills 的漸進式載入¶

    Skills 分三階段載入，對比 MCP 的全量預載：

    1. Metadata（~100 tokens）：掃描描述判斷相關性
    2. Instructions（<5,000 tokens）：匹配時才載入完整指令
    3. Assets：需要時才載入程式碼和檔案

    CLI 的「800-token 技巧」¶

    Scalekit 發現：只用 800 tokens 的 gh CLI 使用提示（skill-augmented CLI），就能比 naive CLI 減少 1/3 的工具呼叫和延遲，是 ROI 最高的做法。

    決策框架¶

    選擇工具整合方式的優先順序（由簡到繁）：

    1. CLI → 有成熟 CLI 的工具（git、docker、gh、kubectl）
    2. Skills → 流程引導、SOP、教 AI 怎麼做
    3. Web API → 遠端服務的直接呼叫
    4. MCP → 僅限以下場景：
    5. 多租戶 OAuth 認證
    6. 跨 AI 平台工具發布
    7. Agent 對 Agent 通訊
    8. 動態工具發現
